# План: покрытие медиачасти business-скрипта (READ-ONLY проверка выполнена)

## Отчет о выполнении проверки (без изменений данных)

Источник: снимок 1677 business-строк, 108 строк с `video_note`/`voice` в `meta.raw`. У всех 108 есть `file_unique_id`, `upload_status=ok`, файл лежит в приватном хранилище `telegram-media` (108/108 объектов на месте).

Гипотеза подтверждена: 87 из 90 исходящих кружков — это два одних и тех же ролика (V01+V02, пара по 60 с), разосланных 43 контактам 29–30.07 (у одного контакта V01 отправлен дважды). Индивидуальных кружков всего 3.

### Уникальные исходящие голосовые (A) — 12 файлов, повторов нет

A01…A12: по 1 отправке каждому из 12 контактов; длительности 9, 15, 19, 22, 22, 22, 36, 41, 100, 119, 138, 426 с; даты 23.07, 29.07 (2), 31.07 (2), 02.08 (4), 01.09, 02.09, 03.09.

### Входящие медиа

Кружки: 3 уникальных (3 контакта, 29.07, по 60 с). Голосовые: 3 уникальных (19.08 — 115 с, 26.08 — 174 с, 28.08 — 45 с). Итого для полного покрытия скрипта нужно прочитать 17 исходящих + 6 входящих = 23 уникальных файла.

### Есть ли расшифровки и штатный доступ

- Сохранённых текстовых расшифровок для этих 23 файлов нет: в `telegram_messages` нет полей transcript; в `contact_files`/`company_files` нет записей с теми же путями; таблицы транскриптов существуют только для звонков (`calls`) и эфиров (`live_event_*`).
- Штатная функция `voice-note-transcribe-summarize` работает только с файлами из `contact-files` и записывает результат в `meta` — для `telegram-media` неприменима без изменений и без записи в БД.
- Прослушать/просмотреть оригиналы штатно можно: диалог Telegram в админке (`telegram-admin-chat`, действия `get_messages`/`get_media_urls`) выдаёт подписанные ссылки на 1 час для сотрудника с правами. Это чтение без изменения данных (побочные эффекты вроде статусов прочтения в этом режиме не проверялись).
- У агента прямого read-only доступа к содержимому приватного bucket нет; расшифровать файлы самостоятельно без нового кода/вызова функций невозможно.

## Возможный следующий шаг (требует отдельного одобрения)

Если нужно текстовое содержание 23 файлов без изменения production:

1. Сотрудник открывает 5 исходящих кружков и 12 голосовых в админ-диалоге по условным кодам V01–V05 / A01–A12 (маппинг код → контакт/дата передаётся отдельно, без file_id) и прослушивает; либо
2. Разовая расшифровка вне production: скачанные сотрудником файлы обрабатываются вне БД, результат не записывается в таблицы. Это не разработка бота и не подключение сервисов.

Без одного из этих шагов медиачасть скрипта остаётся явным пробелом аудита.
